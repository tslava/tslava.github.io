nwarning: a browser extension so nobody mistakes production for dev

Strength
Shipping fast, with tests
My role
Author
Stack
TypeScript · WebExtensions (Manifest V3) · GitHub Actions · Chrome Web Store API · AMO

A side project of mine that part of my team uses at work. When you jump between production and several dev stands of the same web apps, it is easy to do something on the wrong one, slow to open the same page on another stand, and annoying to flip front-end flags through devtools. nwarning fixes all three for Chrome and Firefox.

What it does

  • Always know where you are. A banner and a toolbar badge show the tab's environment. Environments are modelled as one production host with many stands, with wildcard hosts.
  • Switch stands in one click. It opens the same page on another stand, including the AWS console, and keeps the query parameters.
  • Flags without devtools. Tracked localStorage flags appear as coloured chips. Clicking a chip flips the flag and reopens the page, because apps read these flags at startup.

Engineering details

  • The banner never covers the site's own fixed or sticky bars: it hit-tests the viewport, re-checks after CSS transitions and handles background tabs, where animation frames never fire.
  • Firefox moved to Manifest V3, settings sync across the browser profile and can be shared as a file.
  • Releases go through CI, an approval gate and a read-only check of the store credentials, and the two store submissions are independent, so one store's refusal does not block the other.
  • The first version I built by hand with ChatGPT's help, before coding agents; the later overhaul was agentic development with Claude Code.
