Giving AI assistants company context without giving them the keys

Strength
Bringing AI into an engineering team
My role
Designed and wrote it end to end
Stack
Python · MCP · OAuth 2.1 · hybrid search · AWS · Claude

I have been the AI ambassador at a smart parking company since 2022, when GitHub Copilot came out. Since mid-2025 I have led company-wide AI adoption. The foundation of that work is an internal MCP server I designed and wrote end to end: it lets the AI tools our team uses work with our code (100+ repositories), documentation and live product data.

The problem

Our developers and support wanted to ask an assistant real questions, such as "why is this device offline?", and get answers from real data. But an AI agent with broad access to production is a security risk, and an agent with no access cannot answer. I needed a way to give assistants rich context while keeping production safe.

What I built

One server, built around a few design decisions:

  • Safe by default. The assistant reads everything it needs (code, docs, live data) and brings a person a ready result: an answer, a finding, a draft. Actions with an external effect, such as a merge, a published page or an email to a customer, stay with a person, so adopting AI never means losing control.
  • Least privilege, reviewed by hand. Each production API is exposed through an allowlist of read endpoints; anything that could reveal secrets was dropped during review. Cloud access runs under a read-only role that cannot read secrets at all.
  • Gating and audit. Production tools are available only to company accounts, and every call is logged with who made it.
  • Answers you can trust. Every documentation page is tagged as current, plan or report, and search prefers what is current, so the assistant does not answer from an outdated plan.
  • Built for context windows. Large responses are trimmed safely and aggregated on the server, so an assistant gets an answer, not a data dump.

Result

The server became the shared base for our AI work. It does not depend on one vendor: every developer on the team connects it to the AI tool they prefer, such as Claude Code, Codex or Cursor. Investigations and research got much faster, because one assistant can look at code, docs, logs, cloud resources and databases in a single conversation. The same server powers an assistant that drafts customer emails for human review.
